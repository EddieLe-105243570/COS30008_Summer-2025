a. What are the trade-offs between AVL trees and Red-Black trees in terms of
performance and implementation complexity?
Answer: AVL trees maintain stricter balance (height difference ≤ 1) providing faster lookups O(log n) with guaranteed shorter paths, but require more rotations during insertions/deletions making them slower for modifications. Red-Black trees allow looser balancing (black-height property) making insertions/deletions faster with simpler implementation, but may have slightly longer search paths.

b. Explain the concept of RAII and how it helps in resource management in C++.
Answer: Resource Acquisition Is Initialization (RAII) is a C++ idiom where resources are tied to object lifetimes - constructors acquire resources and destructors automatically release them when objects go out of scope. This prevents resource leaks, ensures exception safety, and eliminates the need for manual cleanup calls.

c. Why is std::unique_ptr preferred over raw pointers in modern C++?
Answer: std::unique_ptr provides automatic memory management through RAII, clear ownership semantics with move-only behavior, zero runtime overhead compared to raw pointers, and prevents common errors like memory leaks, double deletion, and dangling pointers.

d. How can we implement a thread-safe BST in C++?
Answer: Implement thread-safety using reader-writer locks (allowing multiple concurrent reads but exclusive writes), or fine-grained locking at node level to reduce contention. Alternatively, use lock-free approaches with atomic operations and compare-and-swap for high-performance scenarios, though this significantly increases implementation complexity.

e. What is the difference between explicit and implicit constructors in C++?
Answer: Implicit constructors allow automatic type conversions (e.g., MyClass obj = 42;), while explicit constructors prevent unintended conversions and require direct invocation (MyClass obj(42);). Explicit constructors improve type safety by preventing unexpected implicit conversions.

f. Explain the use of std::enable_if in template metaprogramming.
Answer: std::enable_if is a template metaprogramming utility that conditionally enables template specializations based on compile-time boolean conditions. It's used with SFINAE (Substitution Failure Is Not An Error) to create type-safe template overloads and constraints.

g. What is the difference between std::move and std::forward ? When should each be used?
Answer: std::move unconditionally casts its argument to an rvalue reference, enabling move semantics by treating the object as disposable. std::forward is used in perfect forwarding to preserve the value category (lvalue/rvalue) of arguments in template functions, maintaining the original reference type.

h. Describe theme complexity of rank queries in an augmented BST.
Answer: O(log n) time complexity by maintaining subtree size information at each node. The rank query traverses from root to target, accumulating counts from left subtrees, without needing to visit all nodes with smaller keys.

i. What are the benefits of using constexpr in C++?
Answer: constexpr enables compile-time evaluation of functions and variables, improving runtime performance by moving computations to compile-time when possible. It also enables template metaprogramming and compile-time constants for array sizes and template parameters.

j. How would you design a BST that supports undo/redo operations?
Answer: Implement using the Command pattern storing operation history in stacks (undo/redo stacks), or use persistent data structures with structural sharing to maintain multiple tree versions efficiently. Each modification creates a new tree version while sharing unchanged subtrees to minimize memory overhead.
